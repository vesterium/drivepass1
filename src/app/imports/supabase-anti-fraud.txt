1. Реализация логики Анти-фрода (SQL в Supabase)
Чтобы реализовать технический кулдаун (1 мойка в 24 часа) и жесткую привязку к госномеру, о которых говорят источники
, нам нужна серверная функция. Это защитит систему от того, что кто-то сможет «накрутить» мойки через фронтенд.
Зайди в SQL Editor в Supabase и выполни этот запрос:
-- Функция проверки: может ли машина мыться прямо сейчас?
CREATE OR REPLACE FUNCTION check_wash_eligibility(vehicle_plate_input TEXT)
RETURNS JSONB AS $$
DECLARE
    last_wash_timestamp TIMESTAMP;
    is_eligible BOOLEAN;
    seconds_remaining INTEGER;
BEGIN
    -- 1. Находим время последней мойки для этого номера
    SELECT created_at INTO last_wash_timestamp
    FROM transactions
    WHERE vehicle_plate = vehicle_plate_input
    ORDER BY created_at DESC
    LIMIT 1;

    -- 2. Если моек не было или прошло больше 24 часов (86400 секунд)
    IF last_wash_timestamp IS NULL OR (now() - last_wash_timestamp) > interval '24 hours' THEN
        is_eligible := TRUE;
        seconds_remaining := 0;
    ELSE
        is_eligible := FALSE;
        -- Считаем, сколько осталось ждать
        seconds_remaining := 86400 - EXTRACT(EPOCH FROM (now() - last_wash_timestamp))::INTEGER;
    END IF;

    RETURN jsonb_build_object(
        'eligible', is_eligible,
        'seconds_remaining', seconds_remaining
    );
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
2. Почему это решает твои баги?
Синхронизация статуса: Теперь твой React-фронтенд будет не просто смотреть на поле «Active», а вызывать эту функцию. Если она возвращает eligible: false, кнопка мойки автоматически заменяется на таймер обратного отсчета. Это обеспечивает бесшовный UX, к которому мы стремимся
.
Генерация QR-кода: Теперь ты можешь генерировать QR-код только тогда, когда функция вернула eligible: true. В QR-код мы зашьем зашифрованную строку: ID_пользователя + Госномер + Текущий_Timestamp. Это защитит тебя от передачи скриншотов другим лицам
.
3. Интеграция на стороне React (Твой следующий шаг)
Когда ты будешь вызывать эту функцию через supabase.rpc('check_wash_eligibility'), твой код на фронтенде будет выглядеть так:
Если eligible: true — Показываем анимированный QR-код.
Если eligible: false — Показываем красивый экран ожидания: «Ваша машина еще чистая! До следующей мойки осталось Х часов».
Что это дает для бизнеса и инвесторов?
Реализация этой логики на уровне базы данных (Security Definer) делает твой проект неуязвимым для взлома через браузер. Это и есть та самая система защиты (The Moat), которая превращает PWA в серьезный финтех-продукт
.
